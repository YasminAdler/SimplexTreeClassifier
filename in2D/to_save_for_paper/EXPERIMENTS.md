# Simplex-Tree Surrogate Experiments

This document describes the paper experiments that live in `in2D/to_save_for_paper/`:
what each dataset is, how it is preprocessed, the neural network being explained,
the simplex-tree surrogate built on top of it, the non-convexity / pruning
machinery, and how the hyperparameters were chosen. All shared code lives in
[`paper_experiments_utils.py`](paper_experiments_utils.py); the originals are
generated by [`_build_paper_notebooks.py`](_build_paper_notebooks.py), while the
`*copy*.ipynb` notebooks hold the scaled-up variants described below.

## 1. Overview and goal

There are two families of notebooks:

- **Original GRU notebooks** (`phoneme`, `wine`, `letter`): the explained network
  is the recurrent `FeatureGRU`.
- **New MLP notebooks** (`banknote`, `blood_transfusion`, `spambase`, `vehicle`,
  `segment`, `waveform`): the explained network is a **fast feed-forward
  `FeatureMLP`** that replaces the GRU so the whole pipeline runs in a fraction
  of the time (the GRU processes each feature as a sequence step; the MLP does
  not, and it scales far better as the feature count grows). Everything else in
  the pipeline is identical.

Each experiment follows the same recipe:

1. Train a small **classifier** (the "network being explained") on a tabular
   dataset scaled to `[0, 1]`. The original notebooks use a GRU; the new
   notebooks use an MLP.
2. Build a **simplex-tree surrogate** of that network: fill `[0, 1]^d` with random
   points labelled by the GRU, then fit a `SimplexTreeClassifier` (a subdivided
   simplex mesh with a `LinearSVC` head per node) to those labels.
3. **Find the non-convex leaves** of the surrogate's decision boundary.
4. **Experiment 1** -- prune the non-convex leaves and show the surrogate's
   *generalisation coefficient* rises (less overfitting).
5. **Experiment 2** -- show that at a non-convex point LIME's explanation vector
   points *out* of the network's target class, whereas at a convex point it stays
   faithful.

### New (MLP) datasets

All six use the standard pipeline (`MinMaxScaler` -> stratified 80/20 split ->

binary and three are multiclass, giving a broader spread of boundary shapes.

| Dataset | Source | Rows | Raw features | Task | Classes |
|---|---|---|---|---|---|
| Banknote | OpenML `banknote-authentication` v1 | 1372 | 4 wavelet stats | genuine vs forged | 2 (`+1` / `-1`) |

Preprocessing common to all: `MinMaxScaler` to `[0, 1]`, then an 80/20
stratified `train_test_split(random_state=42)`. The new datasets keep only the
numeric columns and RFE-select the top 4 features (binary: `LogisticRegression`;
multiclass: multinomial `LogisticRegression`).

### Phoneme
- Binary target: UCI labels `1`/`2` mapped to `+1`/`-1`.
- **Feature selection:** RFE (`LogisticRegression`) keeps the top 4 features.

### Wine Quality (red + white combined)
- White-wine columns are re-aligned to the red-wine column order, then the two
  tables are concatenated.
- Integer quality `3..9` is **binned into 3 ordinal classes**: low (`<= 5`),
  medium (`= 6`), high (`>= 7`).
- **Feature selection:** none. This experiment uses **all 11 features** (no RFE)
  so the surrogate lives in the full 11-dimensional input space.

### Letter Recognition
- The full **26-class** dataset (all letters). String labels are mapped to
  integer indices `0..25`.
- **Feature selection:** RFE keeps the top 4 features.

> Historical note: an earlier variant used a 6-letter confusable subset
> `{M, N, O, Q, U, V}` to force a non-convex boundary. The current `copy`
> notebook runs the full 26-class dataset.

## 3. The model being explained

Both models live in [`paper_experiments_utils.py`](paper_experiments_utils.py)
and share the exact same public interface (`n_classes`, `_logits`, `forward`),
so they are interchangeable in `train_nn` / `predict_classes` / `predict_proba`.

### `FeatureGRU` (original notebooks)

The diabetes-paper RFE-GRU generalised to `K` classes:

- Each of the `d` input features is treated as one time step of a length-`d`
  sequence (input size 1 per step).
- `GRU(input_size=1, hidden_size=64, batch_first=True)` -> `Linear(64 -> out)`.

### `FeatureMLP` (new notebooks) -- the faster replacement

A plain feed-forward network used so the experiments run faster:

- The `d` features go straight into `Linear(d, 64) -> ReLU -> Linear(64, 64) ->
  ReLU -> Linear(64, out)` (it also accepts a `(B, d, 1)` input so it is a true
  drop-in for the GRU).
- No recurrence over the feature "sequence", so training and the many surrogate
  evaluations are considerably cheaper -- and unlike the GRU the cost does not
  grow with the number of features.

Both heads share the same output convention:

- **Binary (`K = 2`):** single output, sigmoid, BCE loss, predictions in `{+1, -1}`.
- **Multiclass (`K > 2`):** `K` outputs, softmax, cross-entropy loss,
  predictions in `0..K-1`.

### Training configuration
Mirrors the diabetes notebook (`train_nn`):

| Hyperparameter | Value |
|---|---|
| Epochs | 200 |
| Batch size | 32 |
| Optimizer | Adam |
| Learning rate | 0.01 |
| Hidden units | 64 |
| Model selection | keep the best-validation snapshot across epochs |
| Seeds | `torch.manual_seed(42)`, `np.random.seed(42)` |

A separate 300-epoch run is trained only to plot the learning curve; the model
used downstream is the 200-epoch one.

## 4. The simplex-tree surrogate

`SimplexTreeClassifier` (from `in2D.classifying.classes.simplex_tree_classifier`):

- **Vertices:** `create_simplex_vertices(n_features)` -- the base simplex over the
  `[0, 1]^d` cube.
- **Head:** `LinearSVC(C=10000, max_iter=20000)`; for multiclass it is
  one-vs-rest, giving one hyperplane per class.
- **`subdivision_levels`:** depth of recursive simplex subdivision. The leaf count
  grows as `(n_features + 1) ** subdivision_levels`, e.g. `5 ** L` for the
  4-feature datasets and `12 ** L` for full-feature wine.

### Fill set
The surrogate is trained to imitate the GRU, not the raw labels:

```
N_FILL = 5000
X_fill = uniform([0,1], (N_FILL, n_features))     # labelled by the GRU
X_fill = vstack([X_fill, X_train])                 # add real points so every class appears
y_fill = nn_pred(X_fill)
```

## 5. Non-convex detection

`find_nonconvex_leaves(model, epsilon=0.05)` returns `{leaf_key: depth}`:

- For every boundary-crossing leaf and every adjacent boundary-crossing neighbour,
  and for **every** OvR hyperplane, run `check_convexity`.
- If the average point lands on the wrong side of the meeting point, both leaves
  are flagged non-convex.
- `depth` = `||average_point - meeting_point|| / shared_face_length`, used to rank
  the "deepest" bends first.
- **`epsilon`** controls strictness: smaller = only severe curvature is flagged.

## 6. Experiment 1 -- pruning reduces overfitting

`build_convex_surrogate(make_model, X_fill, y_fill, epsilon, max_remove_frac, max_iter)`:

- Builds the surrogate, then iteratively removes non-convex leaves **deepest bend
  first**, up to a total budget of `max_remove_frac` of the *initial* leaf count.
- Refits the `LinearSVC` head after every pass; stops when the budget is reached
  or nothing more can be pruned.

**Generalisation coefficient**

```
gen_coef = test_accuracy / train_accuracy      (higher = less overfitting)
```

We report it (against true labels) for the original surrogate, the pruned
surrogate, and the GRU. The claim is that pruning the non-convex leaves lifts the
surrogate's gen-coef, sometimes past the GRU's.

### Pruning cap (`max_remove_frac`)
The main experiment uses **0.25 (25%)**. Each notebook's *Parameter study* section
sweeps `max_remove_frac in {0.10, 0.25, 0.40, 0.60}` and plots the resulting
generalisation coefficient, so the sensitivity to this knob is visible.

## 7. Experiment 2 -- LIME in non-convex regions

- Target class = the class the GRU predicts at `x0`.
- `push_along_lime` fits LIME at `x0`, takes the direction LIME claims increases
  `P(target)`, and steps along it while recording the GRU's true `P(target)`.
- At a **non-convex** point the GRU's `P(target)` drops below 0.5 (it leaves the
  class) even though LIME's local-linear `P(target)` only rises -- LIME's advice
  backfires. At a **convex** control point the GRU stays in-class.
- Test points are stratified by the *depth* of bend in their containing leaf, and
  up to `BUDGET = 80` LIME calls per pool are sampled (LIME is slow).

## 8. Hyperparameter selection rationale

| Choice | How it was made |
|---|---|
| GRU depth/width, epochs, lr, batch | Copied from the diabetes paper notebook for consistency across experiments. |
| `subdivision_levels` | Chosen from the *Accuracy vs subdivision levels* sweep -- pick a depth where the surrogate agrees well with the GRU but has started to overfit the fill points (the regime pruning helps). Phoneme uses 7; wine is capped at 3 because `12**L` explodes with 11 features; letter uses its swept best. |
| `epsilon = 0.05` | Balances flagging genuine bends vs noise; smaller values flag only severe curvature. |
| `max_remove_frac = 0.25` | Default pruning cap; the parameter-study sweep shows behaviour at 0.10-0.60. |
| `C = 10000` (LinearSVC) | Large `C` so each node's linear head fits the local fill labels tightly. |
| `N_FILL = 5000` | Enough GRU-labelled points to define the boundary; note this is sparse in the 11-D wine space. |

## 10. Reproducing

```bash
cd in2D/to_save_for_paper
jupyter nbconvert --to notebook --execute --inplace "phoneme_experiments copy.ipynb"
jupyter nbconvert --to notebook --execute --inplace "wine_experiments copy 2.ipynb"
# letter (26-class) is the slowest -- run when you have time:
jupyter nbconvert --to notebook --execute --inplace "letter_experiments copy.ipynb"
```

### New MLP notebooks

Regenerate them from the builder (writes only the six new notebooks):

```bash
cd in2D/to_save_for_paper
python _build_paper_notebooks.py            # regenerate the six MLP notebooks
python _build_paper_notebooks.py --all      # also rebuild the GRU notebooks
```

Then execute each (they save their outputs in place):

```bash
# from the repo root; _run_nb.py fixes the working directory + kernel
for nb in banknote blood_transfusion spambase vehicle segment waveform; do
    python in2D/to_save_for_paper/_run_nb.py "in2D/to_save_for_paper/${nb}_experiments.ipynb" venvpy
done
```

On a heavily loaded machine, prefix the run with `OMP_NUM_THREADS=1` to stop
PyTorch from oversubscribing threads (this made the runs several times faster in
practice).

Runtime scales with the leaf count `(n_features + 1) ** subdivision_levels`, the
number of OvR hyperplanes (one per class), and the LIME sampling budget.
